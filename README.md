# Wish2Spec

Ассистент заявок пользователей: помогает аналитику разобрать пожелания по документам команды — говорит, есть ли такое уже в системе или среди задач команды, и для нового готовит основу ТЗ. У каждого вывода — ссылка на фрагмент документа, из которого он сделан.

> Проект в разработке: готова версия 0.1 — весь путь от документов до основы ТЗ работает на демо-данных, пока без удобств. Ход работы — в [DEV_NOTES.md](DEV_NOTES.md).

## Что это и зачем

**Проблема.** Пожелания пользователей приходят пачками и сформулированы по-разному: «хочу, чтобы напоминало об оплате», «присылайте письмо, если абонемент кончается». Аналитик для каждого вспоминает или ищет: может, это уже есть; может, такую задачу уже заводили; к какому модулю это относится. Только потом пишет ТЗ — и снова ищет, что уточнить у автора.

**Для кого.** Сотрудник, который разбирает входящие заявки пользователей, — аналитик, владелец продукта, руководитель проекта или администратор службы поддержки (далее в документах проекта — аналитик). Нужны документы о своей системе: справка, прежние ТЗ, список задач, глоссарий.

**Почему AI и почему не обычный чат.** Языковая модель хорошо переформулирует и раскладывает текст по шаблону, но не знает вашу систему и придумает несуществующие модули. Wish2Spec сначала находит в ваших документах фрагменты, близкие по смыслу к заявке (поиск по эмбеддингам, RAG), и даёт модели только их. Вердикт — «уже есть», «похоже на задачу №…», «новое», «требуется уточнение», «вне разработки» — всегда с источниками, которые можно проверить. Поэтому Wish2Spec работает только вместе с документами команды: без них ему не на что опереться.

## Технологии и почему

Подробно, с отвергнутыми вариантами, — в [журнале решений](docs/decisions-log.md).

- **Next.js (App Router) + TypeScript + Tailwind CSS** — интерфейс и серверная часть в одном проекте. Сервер нужен: ключ языковой модели нельзя держать в браузере.
- **AI SDK v6 + `@ai-sdk/openai-compatible`** — подходит любой OpenAI-совместимый сервис (Vercel AI Gateway, OpenRouter, OpenAI): достаточно вписать свой адрес, ключ и модель. Версия 6 работает и на Node 20, 7-я требует Node 22.
- **Локальные эмбеддинги — `@huggingface/transformers`** с моделью `Xenova/multilingual-e5-small` (многоязычная, понимает русский, лицензия MIT). Бесплатно и без лимитов, документы при индексации не покидают компьютер, кроме `npm install` ничего ставить не нужно. Есть запасной режим — эмбеддинги через тот же сервис по ключу.
- **zod** — проверка настроек и входных данных на сервере.
- **Хранение — JSON-файлы в папке `data/`** (не попадает в репозиторий). Деплоя нет, приложение работает локально.

## Как устроено

Путь от документов до основы ТЗ:

1. **Документы режутся на фрагменты.** Markdown — по заголовкам: каждый раздел — отдельный фрагмент, длинный раздел делится по абзацам примерно до 1200 символов, раздел короче 100 символов склеивается с соседним. `.txt` — по абзацам. В начало фрагмента добавляется путь заголовков: «Справка по модулям › Абонементы › Приостановка абонемента».
2. **Каждый фрагмент превращается в эмбеддинг** — вектор смысла текста (локальная модель `multilingual-e5-small`). Индекс хранится в `data/index.json`.
3. **Входящие заявки** разбиваются по пустой строке (если пустых строк нет — по строкам) и сохраняются в `data/requests.json`.
4. **Для каждой заявки** считается её эмбеддинг и находятся 6 ближайших по смыслу фрагментов.
5. **Модель получает заявку и эти фрагменты с номерами** и отвечает строго по схеме: разбор (кто, что, где в системе), вердикт, номер задачи для «похоже», обоснование со ссылками [1], [2] и номера источников. Номера, которых не было среди фрагментов, сервер отбрасывает.
6. **Для вердикта «новое»** второй вызов модели готовит основу ТЗ: название · исходная заявка (дословно, её вставляет код) · проблема и цель · сценарий · критерии приёмки · затронутые модули — только из найденных фрагментов, со ссылками, иначе «связей не найдено» · открытые вопросы (к автору или к команде — решает аналитик).
7. **Карточка заявки** показывает вердикт, разбор, обоснование, источники, основу ТЗ и подсказку «Что дальше»; основу ТЗ и вопросы можно скопировать в Markdown.

Страница отправляет заявки на обработку по одной и сразу показывает готовые; ошибка одной заявки не останавливает остальные. Промпты — в `lib/prompts.ts`.

**Что куда отправляется.** Документы разбиваются на фрагменты и превращаются в эмбеддинги на вашем компьютере (в режиме `EMBEDDINGS_MODE=local`). В сервис языковой модели уходят только текст заявки и найденные к ней фрагменты. В режиме `EMBEDDINGS_MODE=api` в сервис уходят и все фрагменты документов — для расчёта эмбеддингов.

## Термины и вердикты

- **Входящая заявка** (коротко — заявка) — то, что прислал пользователь системы: письмо, сообщение из чата, строка таблицы.
- **Задача** — то, что команда уже завела в трекере (в демо — файл «Список задач»).
- **Основа ТЗ** — то, что готовит Wish2Spec для новой заявки; аналитик проверяет и дописывает её.
- **Фрагмент** — кусок документа, по которому ищутся связи с заявкой; **источник** — фрагмент, на который опирается вывод.

Вердикты:

| Вердикт | Когда | Что дальше |
|---|---|---|
| Уже есть | Функция уже работает: описана в справке или в задаче со статусом «Готово» | Ответить автору, где найти эту функцию |
| Похоже на задачу №N | Есть ещё не сделанная задача о том же | Добавить заявку к задаче — ещё один голос за неё |
| Новое | Такого нет, но это решается доработкой программы, даже если подходящего модуля нет | Проверить основу ТЗ, решить открытые вопросы с автором или командой, завести задачу |
| Требуется уточнение | Из заявки не понять, чего хочет автор | Отправить автору вопросы |
| Вне разработки | Программой не решается: парковка, цены, работа сотрудников | Передать тем, кто за это отвечает, или ответить автору |

## Запуск

Нужен **Node.js 20.9 или новее** (проверено на 20.11.1) и ключ OpenAI-совместимого сервиса языковой модели. Модель должна поддерживать структурированный ответ по JSON-схеме (`response_format: json_schema`), иначе обработка каждой заявки закончится ошибкой.

1. Установить зависимости:
   ```bash
   npm install
   ```
2. Скопировать `.env.example` в `.env.local` и заполнить значения — что означает каждая переменная, написано в самом файле. Все обязательны, кроме `LLM_REASONING_EFFORT` и `EMBEDDINGS_API_MODEL` (нужна только при `EMBEDDINGS_MODE=api`). Для «рассуждающей» модели рекомендуется `LLM_REASONING_EFFORT=none`: на демо-заявках вердиктов, совпавших с ожидаемыми, столько же, сколько с `low`, а ответ в разы быстрее (замер — в [DEV_NOTES.md](DEV_NOTES.md), v0.1). Если чего-то не хватает или значение в неверном формате, маршрут проверки подключений (ниже) назовёт эти переменные; если сервис отклонит ключ или модель — покажет его ответ.
3. Запустить:
   ```bash
   npm run dev
   ```
   и открыть http://localhost:3003. Приложение открывается только на компьютере, где оно запущено, — другие устройства в сети его не видят. Если порт 3003 занят, можно выбрать другой:
   ```bash
   npm run dev -- -p 4000
   ```

При первом расчёте эмбеддингов (первая проверка подключений, а потом — первая индексация документов) локальная модель скачивается с Hugging Face (около 135 МБ, один раз) в папку `data/models/`.

**Маршрут проверки подключений.** При запущенном `npm run dev` скопируйте в адресную строку браузера адрес http://localhost:3003/api/dev/check: модель ответит на короткий вопрос по-русски, а для трёх фраз посчитаются эмбеддинги. В production-сборке этот адрес отвечает 404. Отдельно проверить только локальные эмбеддинги, без ключа:

```bash
npm run check:embeddings
```

## Как попробовать

В папке `demo/` — документы вымышленной студии йоги и 12 входящих заявок.

1. Запустите проект (раздел «Запуск») и откройте http://localhost:3003.
2. **«1. Документация системы»** → «Загрузить файлы» → выберите в `demo/` пять файлов: «Справка по модулям.md», «ТЗ Лист ожидания на занятие.md», «ТЗ Онлайн-оплата абонемента.md», «Список задач.md», «Глоссарий.txt». В первый раз скачивается модель эмбеддингов (около 135 МБ). В списке появятся документы с числом фрагментов.
3. **«2. Входящие заявки»** → «Загрузить .txt» → `demo/Входящие заявки.txt` (или вставьте текст в поле). Под полем появится «Найдено 12» и список заявок → «Добавить 12 заявок в список».
4. **«3. Результат обработки»** → «Обработать 12 заявок». Заявки обрабатываются по одной, у каждой строки виден статус, готовые получают ярлык вердикта.
5. Нажмите на строку — справа (на узком экране — ниже) откроется карточка: разбор, обоснование, источники, для «новое» — основа ТЗ с кнопками «Копировать» (вся основа) и «Копировать вопросы» (только раздел «Открытые вопросы»).

Какие вердикты ожидаются для демо-заявок — в `demo/Ожидаемые вердикты.json`. В демо есть заявки, написанные словами пользователя, а не терминами системы (например, «заморозить абонемент»): связь с документами для них находится через глоссарий.

**На документах своей системы.** Загрузите справку, прежние ТЗ, список задач и глоссарий в `.md` или `.txt`. Лучше всего работают документы с заголовками Markdown (`#`, `##`): по ним документ режется на разделы. У задач в списке — заголовок вида `## Задача №N. Название`, рядом — статус (вердикт «похоже на задачу» берёт номер из заголовка). Документ с тем же названием при повторной загрузке заменяется.

Файлы документов и заявок — в кодировке UTF-8: файл в другой кодировке (например, Windows-1251 — в Блокноте она называется «ANSI») загрузится нечитаемым текстом. В Блокноте кодировку выбирают при «Сохранить как».

Удалить заявки и очистить базу из интерфейса пока нельзя (появится в версии 0.3); чтобы начать заново, остановите сервер и удалите `data/requests.json` (заявки) или `data/index.json` (документы).

**Замеры** (при запущенном `npm run dev`): `npm run measure:reasoning` — прогон демо-заявок с разными `LLM_REASONING_EFFORT` и сверка с ожидаемыми вердиктами; `npm run measure:tokens` — сколько символов приходится на токен модели эмбеддингов во фрагментах из индекса. Замер `measure:reasoning` сам загружает в индекс пять демо-документов (документы с теми же названиями заменяются), а список заявок не трогает. Если вы работаете с документами своей системы, после замера удалите демо-документы в шаге 1 — иначе поиск будет находить фрагменты студии йоги.
