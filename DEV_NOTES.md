## Итерация 0. Каркас

**Статус:** ✅ 2026-10-23 — 2026-10-25

**Цель:** рабочий каркас проекта и проверка двух главных технических рисков до того, как писать продукт: работают ли локальные эмбеддинги на Node 20 и подключается ли языковая модель по ключу.

### План

- [x] Проект Next.js 16 (TypeScript, App Router, Tailwind, ESLint), пакет `wish2spec`, порт 3003, сервер доступен только с компьютера, на котором запущен (`127.0.0.1`)
- [x] `.gitattributes`, `.gitignore` (`/.claude/`, все `.env*` кроме `.env.example`, `/data/`), файлы в CRLF, `git init` без коммита
- [x] Риск 1: локальные эмбеддинги `@huggingface/transformers` на Node 20 — скрипт `scripts/check-embeddings.mjs`
- [x] Настройки `lib/config.ts` из `.env.local`, образец `.env.example`
- [x] Риск 2: ответ языковой модели по-русски через OpenAI-совместимый сервис — маршрут проверки подключений `/api/dev/check`
- [x] Страница-заглушка
- [x] Документы: README (каркас разделов), DEV_NOTES, журнал решений
- [x] Самопроверка: типы, линтер, сборка, страница на `localhost:3003`, CRLF

### Итог

**Риск 1 — локальные эмбеддинги на Node 20: пройден.**

- Пакет `@huggingface/transformers` 4.3.1 работает на Node 20.11.1 без обходных путей (единственное — предупреждение Node `ExperimentalWarning` об импорте JSON-модулей, на работу не влияет).
- Модель — `Xenova/multilingual-e5-small` (ONNX-конверсия `intfloat/multilingual-e5-small`, лицензия MIT), квантованные веса q8, вектор из 384 чисел.
- Загрузка — около 135 МБ: `onnx/model_quantized.onnx` 118 МБ + `tokenizer.json` 17 МБ + два мелких файла настроек. Кэшируется в `data/models/Xenova/multilingual-e5-small/` (путь задан в коде; по умолчанию пакет кладёт модель внутрь `node_modules`).
- Время: первая загрузка со скачиванием — 12,5 с; повторная загрузка из кэша — 1,1 с; один эмбеддинг — 16 мс.
- Смысл различает: «напоминание о неоплаченном счёте» ↔ «уведомление о задолженности» — 0,863; с фразой «смена пароля» — 0,809 и 0,810. Порядок правильный, но разрыв небольшой — у моделей e5 близость почти всех текстов лежит в диапазоне 0,7–1,0 (так написано в описании модели), важен порядок, а не число.
- Внутри Next.js (маршрут проверки подключений) модель работает так же: те же значения близости, первый вызов 1,8 с, следующие — 14 мс. Настраивать `serverExternalPackages` не пришлось: `@huggingface/transformers` и `onnxruntime-node` уже в списке пакетов, которые Next.js 16 не собирает в бандл.

**Риск 2 — языковая модель по ключу: пройден.**

- AI SDK 6 + `@ai-sdk/openai-compatible` 2 работают на Node 20 с Vercel AI Gateway (`https://ai-gateway.vercel.sh/v1`). Проверено маршрутом проверки подключений `/api/dev/check` на модели `alibaba/qwen3.7-flash`: на вопрос по-русски — связный ответ одним предложением по-русски.
- Без настройки рассуждения модель отвечает слишком медленно для пачки пожеланий: у неё в списке AI Gateway метка `reasoning`, и рассуждение включено по умолчанию. Замеры — в «Что узнали».
- Ошибки сервиса доходят до приложения понятным текстом. На Vercel AI Gateway проверены отказ в доступе к модели и неверный ключ — ключ в текст ошибки не попадает.
- Сообщения о недостающих и неверных настройках: называются все проблемные переменные сразу, без значений (проверено без `.env.local`, с неверным адресом и с режимом `api` без модели эмбеддингов).
- В production-сборке (`npm run build` + `npm start`) маршрут проверки подключений отвечает 404.
- Запросы к маршруту с чужих сайтов отклоняются (403) по заголовку браузера `Sec-Fetch-Site`, иначе любая открытая страница могла бы тратить ключ. Проверено в браузере: адрес в адресной строке — 200 и ответ модели; переход по ссылке из терминала — 200; тот же адрес картинкой или ссылкой со страницы другого сайта — 403 с текстом «Запрос пришёл с другого сайта. Скопируйте адрес в адресную строку браузера.», запрос к модели не уходит. Программы вне браузера (curl, скрипты Node) этот заголовок не отправляют и проходят.
- Маршрут отвечает только по адресу `localhost` или `127.0.0.1` (заголовок `Host`) — защита от подмены адреса через DNS (DNS rebinding). Проверено запросами с подменённым `Host`: `localhost` и `127.0.0.1` — 200; чужой домен, даже с `Sec-Fetch-Site: same-origin`, и `localhost.evil.example` — 403 с текстом «Проверка работает только по адресу localhost или 127.0.0.1.».

**Что не работало и гипотезы:**

- `create-next-app` по умолчанию делает первый коммит — запущен с `--disable-git`, `git init` сделан вручную.
- Не ошибка, а риск из документации, учтённый заранее: при включённых Cache Components (их включает шаблон `create-next-app` для Next.js 16.4) GET-обработчик маршрута может выполниться ещё при сборке — тогда проверка вызывала бы модель во время `npm run build`. По документации добавлен `await connection()` в начале обработчика; в сборке маршрут помечен как динамический (ƒ).
- Найдено независимым ревью: по умолчанию `next dev` и `next start` слушают все сетевые интерфейсы (`0.0.0.0`) — приложение было бы видно всем в той же сети. Скрипты привязаны к `127.0.0.1` (почему так — в [журнале](docs/decisions-log.md)); проверено запуском `npm run dev` и `npm start`: по `localhost` открывается, по сетевому адресу компьютера — нет. Смена порта — `npm run dev -- -p 4000` (последний `-p` побеждает, привязка сохраняется).

**Ревью.** Независимое ревью нашло 14 замечаний, критичных нет. Исправлены привязка к `127.0.0.1`, неточности в документах, единое название маршрута проверки подключений, версия `0.0.0`, требование к Node. По решению владельца закрыт и запрос к маршруту с чужой страницы (см. выше). Оставлено одно мелкое замечание: маршрут показывает текст ошибки сервиса как есть — так видна причина отказа, а маршрут доступен только с компьютера, на котором запущен проект, и только при `npm run dev`. Понятный текст вместо сырого ответа сервиса — в v0.3. Повторные круги нашли ещё 6 мелочей в документах и затем 7 замечаний, из них одно важное — ответ 403 на ссылку с другого сайта без объяснения. Исправлены все, в том числе по решению владельца добавлена проверка `Host` от подмены адреса через DNS.

**Что узнали:**

- Абсолютное значение близости у e5 мало что говорит — порог «связей не найдено» надо подбирать на контрольном наборе (v0.2).
- Длинный текст модель обрезает до 512 токенов — это ограничивает размер фрагмента документа (учесть в v0.1 при нарезке).
- Пакет `server-only` защищает модули с ключом от случайного импорта в браузерный код.
- Скорость ответа зависит от модели сильнее, чем от кода: «рассуждающая» модель может отвечать почти минуту даже на короткий вопрос. Параметр `reasoning_effort` (в AI SDK — `providerOptions.<имя провайдера>.reasoningEffort`) AI Gateway принимает. Замер на `alibaba/qwen3.7-flash`, тот же вопрос: без параметра — 46 и 48 с, позже ещё раз 12 с (время сильно скачет); `low` — 13 с (два вызова); `none` — 1,5–2 с (три вызова); ответ по-русски связный во всех случаях. Решение — необязательная настройка `LLM_REASONING_EFFORT` (почему так — в [журнале](docs/decisions-log.md)). Какое значение ставить, `none` или `low`, проверим в v0.1 на демо-пожеланиях.

**История выбора идеи.** До кода сравнивали пять идей продукта. Для каждой — на каких данных пользователя работал бы поиск (RAG) и что делал бы AI; четыре отклонены, выбрана пятая.

1. **Подбор программы из БАД-продукции компании** по пожеланиям пользователя — с проверкой совместимости компонентов и правил приёма (время, интервалы между продуктами).
   - Данные для RAG: каталог продуктов с составами и справочник взаимодействий веществ.
   - AI: подбирает продукты под пожелание, проверяет совместимость компонентов и правила приёма, строит расписание со ссылками на составы и правила.
   - Отклонена: медицинская тематика — высокий риск советов по здоровью; справочник взаимодействий требует проверенных источников.
2. **Посты для канала сетевого консультанта.**
   - Данные для RAG: описания продукции и прошлые посты автора (его стиль).
   - AI: по ссылке на продукт и короткому описанию автора готовит пост в его стиле.
   - Отклонена: мало отличается от обычного чата с моделью — RAG здесь почти ничего не добавляет.
3. **Сказочник с памятью семьи.**
   - Данные для RAG: профиль ребёнка (возраст, любимые герои, темы, которых избегать), «мир серии» с персонажами, прошлые сказки и правки родителя.
   - AI: пишет новую сказку, которая продолжает серию и не противоречит прошлым, обыгрывает ситуацию, описанную родителем, и проверяет текст по профилю.
   - Отклонена: пока сказок мало, вся база помещается в запрос целиком, и поиск не нужен; рынок генераторов сказок занят; качество текста сильно зависит от модели.
4. **Подбор рецептов из своей коллекции.**
   - Данные для RAG: собственная коллекция рецептов (заметки, сохранённые страницы).
   - AI: приводит рецепты к единому виду, находит подходящий по тому, что есть дома, а если чего-то не хватает — адаптирует с заменами и помечает изменения относительно оригинала.
   - Отклонена: рынок приложений для рецептов плотный, боль слабее, чем у остальных идей.
5. **Ассистент заявок пользователей.**
   - Данные для RAG: документы команды (справка, прежние ТЗ, список заявок, глоссарий).
   - AI: разбирает пожелание, находит связанное, выносит вердикт с источниками, для «нового» готовит основу ТЗ.
   - Выбрана: регулярная рабочая боль, автор знает её изнутри; продукт опирается на документы команды, поэтому поиск по ним (RAG) здесь основа, а не добавка к обычному чату; у каждого вывода есть источник.

**Решения** (подробно — в [журнале](docs/decisions-log.md)): кто работает с продуктом; стек; AI SDK v6 и OpenAI-совместимый сервис; необязательная `LLM_REASONING_EFFORT`; локальные эмбеддинги с запасным режимом `api`; модель `multilingual-e5-small` q8 и кэш в `data/models/`; хранение в JSON; без деплоя; приватность; форматы; демо; порт 3003; сервер доступен только с компьютера, на котором запущен; версия `0.0.0`; защита маршрута проверки подключений от запросов с чужих сайтов; документы проекта.
